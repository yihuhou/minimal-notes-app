# Repository Instructions

## Privacy in public content

- Treat README files, documentation, examples, fixtures, screenshots, commit
  messages, and other tracked repository content as public.
- Never copy, quote, or closely paraphrase a user's real notes or private data
  into public repository content. This includes applications, deadlines,
  journals, health information, relationships, locations, identifiers, and
  personal plans.
- Use clearly fictional, generic examples. When documenting parser behavior
  from a user-provided phrase, preserve only the syntax needed to demonstrate
  the feature and replace the subject matter with neutral wording such as
  `两周内提交项目报告`.
- Before committing public-facing examples, review them for text derived from
  private records. If there is any doubt, replace the example rather than
  publishing it.
